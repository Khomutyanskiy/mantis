# Mantis — видеоаналитика витрины

Из видеопотока считает три метрики:

| Метрика | Как считается |
|---|---|
| **Прошли** | трек человека (точка ног) пересёк линию подсчёта; учитывается направление |
| **Притормозили** | в зоне витрины скорость < порога суммарно ≥ `min_slow_seconds` **или** человек в зоне ≥ `dwell_seconds` |
| **Посмотрели** | в зоне витрины голова повёрнута к витрине суммарно ≥ `min_look_seconds` |

Стек: YOLO11-pose (детекция людей + 17 ключевых точек) → ByteTrack (ID) → логика в `mantis/analytics.py`.
Поворот головы оценивается по точкам носа, глаз и ушей (`mantis/headpose.py`), отдельная нейросеть не нужна.

## Установка

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
```
При первом запуске веса `yolo11n-pose.pt` (6 МБ) скачаются автоматически.

## Запуск

```bash
# 1. Разметить линию и зону витрины на кадре своего видео
python tools/calibrate.py --source video.mp4 --base config.example.yaml --out config.yaml

# 2. Обработать видео / поток
python run.py --source video.mp4 --config config.yaml --device mps      # Mac M1+
python run.py --source rtsp://user:pass@ip/stream --config config.yaml --show
python run.py --source 0 --config config.yaml --show                     # веб-камера
```

## Живой режим (камера / эмуляция камеры из файла)

Флаг `--live` включает поведение живой камеры:
- кадры приходят в реальном темпе;
- обрабатывается всегда самый свежий кадр, а отставшие пропускаются, поэтому задержка не копится;
- время событий берётся по реальным часам.

Видео с телефона автоматически разворачивается по метаданным (вручную: `--rotate 90`), 4K уменьшается до 1920. В окне видны рамки людей с ID, счётчики, FPS обработки, число пропущенных кадров и задержка. Клавиши: `q`/`Esc` — выход, пробел — пауза, `f` — во весь экран (или сразу `--fullscreen`).

**Вариант А — файл как камера** (проще всего):
```bash
python run.py --source ../IMG_1761.MOV --config config.img1761.yaml --live --loop --show --device mps
```

**Вариант Б — настоящий RTSP-поток.** Тот же путь, по которому пойдёт боевая IP-камера:
```bash
brew install mediamtx ffmpeg                       # один раз
./tools/fake_camera.sh ../IMG_1761.MOV             # терминал 1: «камера» rtsp://localhost:8554/cam
python run.py --source rtsp://localhost:8554/cam --config config.img1761.yaml --live --show --device mps   # терминал 2
```
Если RTSP-поток обрывается, программа сама переподключается.

В live-режиме:
- события печатаются в консоль и сразу пишутся в `events.csv`;
- `summary.json` обновляется каждые `summary_every_seconds`;
- видео по умолчанию не пишется (включить флагом `--save-video`).

Скорость: на CPU примерно 3–5 кадров/с, на Mac M1+ с `--device mps` примерно 15–30. Если FPS мало, уменьшите вход сети: `--imgsz 640`.
Для подсчёта людей хватает 10–15 кадров/с.

## Результат

Результат — в `output/<дата_время>/`:
- `events.csv`: события `passed / slowed / looked` с временем и ID трека;
- `tracks.csv`: сводка по каждому человеку (время в зоне, время взгляда, минимальная скорость);
- `summary.json`: итоговые счётчики и конверсии (`slowed_rate`, `looked_rate` = доля от прошедших);
- `annotated.mp4`: размеченное видео (отключается флагом `--no-video`).

Цвет рамки: серый — просто трек, белый — прошёл линию, зелёный — притормозил, жёлтый — посмотрел. Над рамкой показаны ID и текущая скорость (ростов в секунду).

## Размещение камеры

- **Для «посмотрел»** камеру ставить в витрине на уровне 1,8–2,5 м, направить на прохожих (`showcase_direction: camera`). Лицо должно занимать от ~40 px.
- Если камера сбоку или сверху, используйте `left`/`right`. Это заметно менее точно.
- Линию подсчёта ставьте поперёк основного потока, зону — на участке тротуара непосредственно перед витриной.

## Настройка порогов

Все пороги в `config.example.yaml` с комментариями. Порядок калибровки: прогнать 10–15 минут видео, вручную пересчитать по `annotated.mp4` и подстроить `speed_threshold`, `dwell_seconds`, `max_yaw`, `min_look_seconds`.

Замечания:
- `slowed` и `looked` считаются для всех, кто был в зоне, даже если человек не пересёк линию (например, подошёл и ушёл обратно). Поэтому конверсия может превысить 100%, если зона шире потока через линию.
- Мелкие и дальние люди детектируются лучше при `imgsz: 1280`. На CPU это примерно 3 кадра/с, на Apple M-серии с `mps` и на NVIDIA заметно быстрее. Для реального времени можно обрабатывать каждый 2–3-й кадр или взять GPU/Jetson.
- Для точности выше можно взять модель `yolo11s-pose.pt` / `yolo11m-pose.pt`.

## Приватность (152-ФЗ)

Лица не идентифицируются и не сохраняются отдельно, хранятся только обезличенные события и ID треков в пределах сессии. Для боевого режима отключайте `save_video`.
